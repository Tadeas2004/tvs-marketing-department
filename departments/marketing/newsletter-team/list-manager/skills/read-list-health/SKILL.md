# read-list-health

One honest read on the list, from whatever numbers exist right now. No live connection needed — a CSV, a screenshot, or numbers typed straight into the chat all work.

## Ask before you read

1. **What do you actually have?** Total subscribers, opens/open rate, unsubscribes, new signups — whatever was tracked. Don't ask for a number that was never captured.
2. **Compared to what?** Check this hire's Memory section for the last logged snapshot first. If there's nothing to compare to, say this reading is the baseline, not a trend, and don't manufacture a direction that isn't there yet.
3. **Which list is this?** The old Gumroad list or the new Substack one, once that exists. Never assume — `brand/channels.md` already flags these as different audiences, built for different things.

## Read it

- State growing, flat, or aging in one line, with the real numbers behind it. No hedging past that line.
- Flag the quiet ones: a rising unsubscribe rate right after a topic or platform shift is a real signal, not noise — say so plainly instead of softening it.
- Never infer list quality from size alone. A list built for a different audience than the current ICP (see `brand/channels.md`'s own caveat on the Gumroad list) is not that many potential buyers — say what the number actually represents, not what it sounds like it represents.
- If the numbers are too thin to say anything real, say that plainly instead of forcing a verdict.

## Deliver

One short read: the verdict, the number behind it, and the one thing worth watching next. Log the snapshot (date, list, numbers, verdict) in this hire's Memory section so the next run has something real to compare against — a reading that isn't saved anywhere just repeats the "no baseline" problem next time.
