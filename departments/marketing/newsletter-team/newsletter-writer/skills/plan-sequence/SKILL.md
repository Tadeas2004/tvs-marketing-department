# plan-sequence

A sequence is a bet across several emails, not one email repeated five times. This skill decides the shape before write-issue drafts a single line.

## Read these first, every time

- `business.md`: what's actually being sold and what stage the business is at — pre-revenue changes what a sequence can honestly claim
- `brand/icp.md`: who's supposed to end up booking the call
- `brand/channels.md`: the give/prove/invite funnel split — a sequence is that split compressed into a handful of emails, not an excuse to skip straight to the ask
- `brand/lead-gen-playbook.md`: which acquisition stage this list actually sits in, and what's already been decided about how it should be used
- `brand/friction-points.md` and `brand/contrarian-take.md`: what the eventual invite is, and is not, allowed to promise

If any of these are thin or silent on the actual list being emailed, say so and ask before planning around a guess.

## Ask before you plan

1. **What's the goal of this push?** One sentence — a migration, a pivot, a launch, a re-engagement.
2. **Who's actually on this list right now, and does that match the ICP?** If it doesn't, the plan says so plainly — a sequence has to be honest about who it's really talking to, not who it wishes was reading.
3. **What's the one invite at the end pointing at?** Usually the same answer as channels.md's "one next step."
4. **Any real constraint on count or timing?** A hard cap on free spots, a platform-migration deadline, whatever's actually true.

## Build the plan

- Lay out each issue as one line: **the job** (give / prove / invite), **the one idea**, **what it can't claim yet** — pulled straight from friction-points.md's unsolved list and contrarian-take.md's "never pretend to be further along than you are" rule.
- Give before you ask. At least one give-or-prove issue before the first invite; never plan two invites back to back — the same rule channels.md sets for public posts, applied here.
- The invite issue names its real constraint plainly. A spot count or deadline only belongs in the plan if it's an actual limit, never invented pressure.
- Keep the plan to a table or short list the owner can approve in one read. This skill does not draft copy — write-issue does that, one approved issue at a time.

## Deliver

Give the plan, issue by issue, and stop. Wait for a yes, or for changes, before write-issue drafts the first one. A plan reshaping after this is normal — it's supposed to be cheap to change before any copy exists.
